# 완료보고 작성규칙

> 원본 규칙: `01.관리문서/완료보고서.md`, `CLAUDE.md`의 Document Chaining / Gate-Check Rules

## 기본 규칙

- **산출물 번호**: #17 (완료보고서)
- **전제조건**: #16 테스트결과보고서 완료 + 15개 이상 산출물 완료
- **실체 검증**: Gate-Check에서 15개 이상 산출물 완료를 확인합니다
- **파일명**: `완료보고서_YYYY-MM-DD.md` (날짜 = 완료일)
- **데이터 소스**: 착수보고서(계획 대비 최종 실적), `.progress.md`, 테스트결과보고서, GitHub Issues 최종 현황, 배포 상태

## 자동 생성

```
claude "착수보고서 계획 대비 최종 실적을 정리하여 완료보고서를 작성해줘"
```

발행본은 `10.보고서/R3.완료보고/완료보고서_YYYY-MM-DD.md`로 저장합니다.

## 문서 구성

`템플릿.md`의 7개 섹션을 그대로 사용합니다.

| # | 섹션 |
|---|------|
| 1 | 프로젝트 완료 요약 (최종 판정: 완료 / 조건부 완료 / 미완료) |
| 2 | 산출물 최종 현황 (문서 / 코드 / 배포) |
| 3 | 품질 평가 (테스트 결과 요약 / 미해결 이슈) |
| 4 | 계획 대비 변경 이력 |
| 5 | GitHub Issues 최종 현황 |
| 6 | 교훈 (잘된 점 / 개선할 점 / 향후 제언) |
| 7 | 인수인계 사항 |

## 승인

문서 하단의 **승인 (User Sign-off)** 체크가 완료되어야 프로젝트가 종료됩니다.

## 출력 변환

발주처 제출본은 PDF로 변환합니다 (`doc-report` 또는 `pdf-report` 스킬).
변환 파일명에는 `_YYYYMMDD_HHMM` 타임스탬프를 붙입니다 (`CLAUDE.md` "산출물 HTML/PPTX 출력 파일명 규칙").
