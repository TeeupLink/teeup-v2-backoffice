## 1. 전체 사이트맵

메뉴는 "업무 → 운영 데이터 → 콘텐츠 → 수익 → 시스템" 순서입니다. 매일 처리하는 업무(가입신청·문의·신고)를 맨 위에 둬서 대시보드를 거치지 않아도 바로 들어갈 수 있게 했습니다.

```mermaid
flowchart TD
    ROOT[티업링크 백오피스] --> DASH[대시보드]
    DASH --> DASH1[오늘 처리할 일 / 운영 요약]
    DASH --> DASH2[KPI]

    ROOT --> WORK[업무]
    WORK --> W1[가입신청]
    WORK --> W2[1:1 문의]
    WORK --> W3[신고]

    ROOT --> OPS[운영]
    OPS --> O1[회원]
    OPS --> O2[클럽]
    OPS --> O3[라운딩]
    OPS --> O4[소셜]

    ROOT --> CON[콘텐츠]
    CON --> C1[공지]
    CON --> C2[FAQ]
    CON --> C3[약관]

    ROOT --> REV[결제]
    REV --> R1[결제 내역]
    REV --> R2[구독]
    REV --> R3[요금제]
    REV --> R4[청구 실패]
    REV --> R5[빌링 샌드박스]

    ROOT --> SYS[시스템]
    SYS --> S1[관리자]
    SYS --> S2[감사 로그]

    ROOT -.헤더.-> H1[통합 검색]
    ROOT -.헤더.-> H2[알림 벨]
    ROOT -.헤더.-> H3[마스킹 토글]
    ROOT -.헤더.-> H4[내 프로필]

    O1 --> O1D[회원 상세: 기본 / 골프 / 클럽 / 모임 / 활동 / 결제 / 약관]
    O2 --> O2D[클럽 상세: 개요 / 멤버 / 가입신청 / 공지 / 규정 / 회비 / 모임]
    O3 --> O3D[라운딩 상세: 개요 / 참가자 / 팀 / 점수 / 정산 / 통계]
    O4 --> O4D[소셜 상세: 개요 / 참가자 / 정산]
```

### 1.1 기존 메뉴 대비 변경

| 기존 | 재구축 | 이유 |
|------|--------|------|
| 사용자관리(회원·관리자) | 회원 → 운영, 관리자 → 시스템 | 회원은 일상 업무, 관리자는 드문 설정 |
| 클럽 상세 안의 "가입승인관리" 탭만 존재 | **업무 > 가입신청** 통합 목록 신설 (클럽 상세 탭도 유지) | 클럽별로 들어가지 않고 한 번에 처리 |
| 클럽 공지·규정·회비 = 별도 페이지 | 클럽 상세의 탭 | 화면 이동 감소 |
| 라운딩 팀·점수·정산·통계 = 별도 페이지 | 라운딩 상세의 탭 | 화면 이동 감소 |
| 시스템 > 설정(비밀번호 + 약관 4탭) | 비밀번호 → 내 프로필, 약관 → 콘텐츠 > 약관(버전 관리) | 역할 교차 문제 해소, 버전 도입 |
| 알림 페이지(localStorage) | 헤더 알림 벨만 | 범위 결정 |
| 클럽 개설 신청 2화면(고아) | 삭제 | 승인 없이 자유 등록 (2026-10-28 결정) |

## 3. 권한 매트릭스

`R`=조회, `W`=조회+변경, `-`=메뉴 숨김·라우트 403. SUPER_ADMIN은 전 항목 `W`. 이 표가 프론트 라우트 메타·메뉴·대시보드 카드와 백엔드 `require_roles`의 **단일 기준**입니다.

| 메뉴 / 화면 | CLUB | MEETING | USER | CONTENT | SUPPORT | 백엔드 변경 필요 |
|-------------|------|---------|------|---------|---------|------------------|
| 대시보드(오늘 할 일·요약) | R | R | R | R | R | 카드별 범위 필터 |
| KPI | - | - | - | - | - | SUPER 전용 |
| 가입신청 | W | - | - | - | - | 신설 |
| 1:1 문의 | - | - | - | - | W | |
| 신고 | - | - | - | - | W | 신설 |
| 회원 | - | - | W | - | R | **SUPPORT 조회 추가** (CS 응대 시 회원 확인) |
| 클럽 | W | R | - | - | - | MEETING 조회는 lookup으로 충분하면 생략 |
| 라운딩 · 소셜 | R | W | - | - | - | CLUB 조회 = 클럽 상세 모임 탭 |
| 공지 · FAQ · 약관 | - | - | - | W | - | |
| 결제 · 구독 · 요금제 · 청구 실패 | - | - | - | - | R | **SUPPORT 결제 조회 추가** (환불 문의). 취소·환불은 SUPER |
| 빌링 샌드박스 | - | - | - | - | - | SUPER 전용 |
| 관리자 | - | - | - | - | - | SUPER 전용 |
| 감사 로그 | - | - | - | - | - | SUPER 전용 |
| 내 프로필 · 비밀번호 | W | W | W | W | W | 기존 인증만 |
| 공용 조회(lookup) | R | R | R | R | R | 신설 |
| 헤더 검색 | 범위 내 | 범위 내 | 범위 내 | 범위 내 | 범위 내 | 결과를 위 표로 필터 |

> 표에서 **굵게** 표시한 SUPPORT 조회 권한 2건은 기존에 없던 것입니다. CS 담당이 문의에 답하려면 회원·결제를 봐야 하므로 추가를 제안합니다. 조회는 감사 로그(VIEW_PII)로 남습니다.

## 4. 사용자 흐름

### 4.1 가입신청 일괄 승인 (Top 1 업무)

```mermaid
flowchart LR
    A([로그인]) --> B[대시보드]
    B -->|가입신청 대기 N 카드| C["/join-requests?status=PENDING"]
    C --> D{전부 승인?}
    D -->|예| E[헤더 체크박스 전체 선택]
    E --> F[BulkActionBar 승인]
    D -->|일부 거절| G[행 선택]
    G --> H[거절 + 사유]
    F --> I[결과 Toast: 성공 n / 실패 m]
    H --> I
    I -->|실패 있음| J[실패 목록 다이얼로그]
    I --> K([목록 자동 갱신])
```

클릭 수: 카드 1 → 전체 선택 2 → 승인 3 (확인 다이얼로그는 승인에는 띄우지 않고 거절에만 띄웁니다).

### 4.2 1:1 문의 답변 (Top 2 업무)

```mermaid
flowchart LR
    A[대시보드] -->|미답변 N| B["/inquiries?status=PENDING"]
    B -->|행 클릭| C["/inquiries/:id"]
    C --> D{회원 확인 필요?}
    D -->|예| E[작성자 링크 → 회원 상세 활동 탭 새 탭]
    E --> F
    D -->|아니오| F[답변 입력]
    F --> G[등록 + 답변완료 전환 ON]
    G --> H[목록으로 / 다음 미답변]
```

상세 화면에 "다음 미답변" 버튼을 둬서 목록으로 돌아가지 않고 연속 처리합니다.

### 4.3 오늘 라운딩 운영 (Top 3 업무)

```mermaid
flowchart LR
    A[대시보드] -->|오늘 라운딩 N| B["/rounds?date=today"]
    B --> C["/rounds/:id"]
    C --> T1[참가자 탭: 확정 확인]
    T1 --> T2[팀 탭: 자동 편성 → 수동 조정]
    T2 --> T3[점수 탭: 총타 일괄 입력]
    T3 --> T4[정산 탭: 비용 입력 → 납부 체크]
    T4 --> T5[개요 탭: 상태 COMPLETED]
```

### 4.4 회원 문의 대응 (DB 직접 조회 제거)

```mermaid
flowchart LR
    A[헤더 검색: 닉네임·이메일] --> B["/users/:id"]
    B --> C[활동 탭: 최근 로그인·가입·참여 이력]
    B --> D[결제 탭: 결제·환불 상태]
    B --> E[클럽 탭: 소속·역할]
    C & D & E --> F([문의 답변에 반영])
```

### 4.5 세션 만료·권한

```mermaid
flowchart TD
    A[아무 화면에서 요청] --> B{응답}
    B -->|401 / 인증 403| C["/login?next=현재경로"]
    C --> D[재로그인] --> E[원래 경로 복귀]
    B -->|권한 403| F[SCR-002 권한 없음]
    G[URL 직접 진입] --> H{라우트 roles 포함?}
    H -->|아니오| F
    H -->|예| I[화면 렌더]
```

### 4.6 신고 처리

```mermaid
flowchart LR
    A[알림 벨 / 대시보드 신고 대기] --> B["/reports?status=PENDING"]
    B --> C["/reports/:id"]
    C --> D[대상 미리보기 확인]
    D --> E{조치 필요?}
    E -->|예| F[대상 바로가기 → 클럽 비활성 / 회원 비활성]
    F --> G[신고 RESOLVED + 메모]
    E -->|아니오| H[DISMISSED + 메모]
```

## 5. 화면 간 공통 이동 규칙

| 상황 | 이동 |
|------|------|
| 목록 행 클릭 | 상세 (Ctrl/Cmd 클릭 = 새 탭 — 행은 `<a>`로 렌더) |
| 등록 완료 | 생성된 상세 |
| 수정 완료 | 상세 (탭 유지) |
| 삭제 완료 | 목록 (이전 필터 유지 — 목록 URL을 상세 진입 시 `state`에 보관) |
| 상세 "목록으로" | 진입했던 목록 URL (없으면 기본 목록) |
| 다른 도메인 참조 (클럽명·회원명 등) | 해당 상세 링크. 권한 없으면 링크 대신 텍스트 |
| 대시보드 카드 | 필터가 걸린 목록 |
