## 3. 시험 중 발견해 고친 문제

| 이슈 | 내용 | 심각도 | 조치 |
|------|------|--------|------|
| BE#71 | 백엔드가 **모든 요청의 헤더·본문을 표준 출력에 기록** — 로그인 비밀번호 원문, Authorization 토큰, 쿠키, CSRF 토큰이 운영 Docker 로그에 남음 (처음 커밋부터) | 고 | 미들웨어 제거. 재시험 결과 로그의 비밀번호·토큰 0건 |
| 시나리오 | 가입신청 승인 단계가 "승인" 글자만 확인해 실패 응답도 통과로 잡을 수 있었음 | 저 | 정상·예외 두 케이스로 나눠 문구까지 확인 |

재구축 과정(#18~#32)에서 함께 고친 백엔드 결함은 각 PR(BE#58~#70)과 CHANGELOG 에 있습니다. 주요 항목: 관리자 알림이 회원에게 푸시로 감, 임시 저장 공지가 전체 회원에게 알림, 게시 약관 본문 덮어쓰기, 정산의 id 공간 혼동, 관리자 비밀번호 솔트 없는 SHA-256, 마지막 최고 관리자 강등 가능, 역할 없이 등록하면 최고 관리자.

## 5. 배포 순서 (교체 배포 #33)

| 순서 | 작업 | 비고 |
|------|------|------|
| 1 | 백엔드 `dev` 에 BE#71 병합 → 운영 배포 | 로그 노출부터 막는다 |
| 2 | 운영 DB 에 SQL 적용: `scripts/add_admin_audit_logs.sql`, `scripts/add_user_activity_logs.sql`, `scripts/add_admin_notifications.sql` | 감사·활동 로그·관리자 알림 테이블 |
| 3 | 하루 한 번 `scripts/purge_user_activity_logs.py` 실행 등록 | 활동 로그 1년 보관 |
| 4 | 백오피스 `rebuild` → `dev` 병합, `npm run build` → `dist/` nginx 배포 | 빌드 명령·출력 경로 변경 없음 |
| 5 | 배포 후 검수 체크리스트 7항목(CLAUDE.md) 확인 | 특히 SPA 새로고침, 역할별 403 |
| 6 | 예전 백오피스 접속 중단 확인 후 BE#72 병합·배포 | 리더 강등 차단, 클럽 목록 기본값 |
| 7 | R-01, R-02 조치 | 로그·계정 |

관리자 비밀번호는 PBKDF2 로 바뀌며 각자 다음 로그인 때 자동 전환됩니다. 이 버전 배포 후 이전 백엔드로 되돌리면, 그 사이 로그인한 관리자는 로그인할 수 없습니다(BE#67 참고).
