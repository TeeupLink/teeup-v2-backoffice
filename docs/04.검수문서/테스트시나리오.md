## 1. 테스트 범위

| 구분 | 대상 | 도구 | 위치 |
|------|------|------|------|
| 단위·화면 테스트 (프론트) | 공통 컴포넌트, 화면별 동작, API 호출 본문 | Vitest + Testing Library (API 는 가짜) | `src/**/*.test.ts(x)` |
| API 테스트 (백엔드) | 관리자 API 의 권한·검증·감사 로그 | pytest + SQLite 메모리 DB | `teeup-v2-backend/test/test_admin_*.py` |
| 통합 시험 (교체 배포) | 실제 백엔드 + 실제 DB + 실제 브라우저로 핵심 업무 흐름 | Playwright, 로컬 MariaDB 시험 DB | 아래 3장 TC-001~033 |

### 통합 시험 환경

| 항목 | 내용 |
|------|------|
| 백오피스 | `rebuild` 브랜치, Vite 개발 서버 (`/api` 프록시) |
| 백엔드 | `dev` 최신 + 보안 수정(#71), uvicorn |
| DB | 로컬 MariaDB 12.3 시험 전용 인스턴스(포트 3317), 모델로 테이블 생성 후 가짜 데이터 투입 |
| 시험 데이터 | 관리자 6명(역할별 1명, PBKDF2 비밀번호), 회원 40명, 클럽 5개(1개 비활성), 라운딩 12·소셜 3, 문의 4, 신고 3·차단 1, 약관 2종, 로그인 기록 20일 |
| 브라우저 | Chromium(headless), 데스크톱 1440×900, 모바일 390×844 |
| 판정 기준 | 기대 화면이 나오고, **그 단계에서 400 이상 API 응답·화면 오류·콘솔 오류가 0건** |

운영 DB·운영 계정은 쓰지 않았습니다. 시험마다 DB 를 처음 상태로 되돌린 뒤 실행합니다.

| 항목 | 내용 |
|------|------|
| 관련 기능 | F-044 |
| 사전 조건 | 강남 골프회: 리더 golfer00, 활동 멤버 golfer03 |
| 테스트 단계 | 1. 클럽 상세 → 멤버 탭 2. golfer03 행 "리더로" 3. 확인 창 "리더로 지정" |
